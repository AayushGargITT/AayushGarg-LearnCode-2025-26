Formatting Violations Identified

1)Horizontal Formatting Issues
Multiple statements on one line(this.logger=logger;this.notifier=notifier;)
No spacing around opeartors
Long lines that could be broken for readability
No spacing after commas in method parameters

2)Vertical Formatting
No blank lines between logical sections
Lack of vertical openness between concepts

Team Java Formatting Standards

1. Horizontal Formatting
1.1 Line Length
Maximum line length: 120 characters
Preferred line length: 80-100 characters

1.2 Indentation
Use 4 spaces (never tabs)
Indent each nested level consistently

1.3 Spacing
Always add spaces around binary operators: =, +, -, *, /, ==, !=, <, >, &&, ||
Always add space after commas in parameter lists

1.4 Horizontal Alignment
Do NOT use column alignment for variable declarations or assignments

2)Vertical Formatting

2.1 File Organization (Top to Bottom)
Package declaration
Import statements (grouped and sorted)
Class declaration
Instance fields
Constructors
Public methods
Private/protected methods

2.2 Blank Lines
Use Blank Lines To Separate:
Between methods (1 blank line)
Between logical sections within methods (1 blank line)
Between class fields and first method (1 blank line)

2.3 Vertical Density
Keep related code close together
Don't separate closely related lines with blank lines

2.4 Newspaper Metaphor
Most important (high-level) methods at the top
Details (helper methods) toward the bottom

2.5 Caller Before Callee
Methods should be ordered so callers appear before methods they call
Helps with top-down reading
